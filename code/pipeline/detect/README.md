# detect — 偵測

事件前後 SAR 變化偵測 → 新增水體／崩塌 → 疑似堰塞湖判定。

| 檔案 | 內容 | 狀態 |
|---|---|---|
| `water.py` | 水體萃取：光學 NDWI + SAR 低回波（Otsu，退回 −18 dB）；`change_detection` 算新增水體 | 完成 |
| `landslide.py` | 崩塌變化偵測：振幅比值法（GRD），\|Δσ⁰\| ≥ 3 dB，扣水體／疊置／陰影、去小碎塊 | 完成（相干性法 SLC 沒做） |
| `barrier_lake.py` | 堰塞湖判定：新增水體 × 河道相交 × 鄰近崩塌（DEM 檢核壩體在下游）× 多時相持續 → A/B/C | 完成 |

前處理在 `pipeline/preprocess/`：`sar.py`（讀檔、Lee 濾波、對齊檢查）、
`mask.py`（雷達陰影／疊置／陡坡遮罩）。輻射與地形校正交給 Google Earth
Engine 的 `COPERNICUS/S1_GRD`，不需要 SNAP。

## 分級

| 等級 | 條件 | 建議動作 |
|---|---|---|
| A | 河道相交 + 鄰近崩塌（壩體在下游）+ 多時相持續 | 立即通報 |
| B | 河道相交 + 鄰近崩塌（單期／未持續） | 排下一期影像複核 |
| C | 河道相交，附近無崩塌（或崩塌沒到河床） | 列觀察；崩塌可能落在陰影／疊置區 |
| — | 不貼河道的新增水體 | 不列入 |

## 已知限制

- 陰影／疊置只做局部坡面判定，沒有沿距離向射線追蹤（被遠處山脊擋住的陰影抓不到）。
- 坡度 > 20° 一律不當水，湖緣貼著陡峭山壁的部分會被低估。
- D8 河網沒有先填窪，窪地會截斷累積；主要用途是補事件前影像上太窄看不到的河道。
- 崩塌落在疊置／陰影區時偵測不到，湖會被降為 C 級，要靠升降軌互補或光學影像。

- 還沒用真實 Sentinel-1 跑過。GEE 匯出腳本在 `scripts/analyze_sar_change.py` 開頭，
  其中 `orbit = 69` 是佔位值，要換成事件前後都有影像的軌道號。

## 開發時遇到的問題

1. **湖被原河道切成兩半。** 原河道是事件前水體，扣掉後同一座湖變成兩塊。
   `classify` 先把新增水體外擴 3 像元再分塊，面積仍只算新增水體。
2. **湖岸出現假崩塌。** 濾波後水陸交界的回波降了幾 dB，又沒被判成水，
   沿湖岸冒出一圈「崩塌」，還讓「崩塌只在山坡上」的情境被判成有壩體。
   現在把水體外擴 2 像元後從崩塌中排除。
3. **窄河道被濾波抹掉。** 5×5 Lee 濾波會把 3 像元寬河道的邊緣拉到門檻以上。
   判水改用 3×3，崩塌維持 5×5（3 dB 門檻需要較強的雜訊抑制）。

## 驗證

合成山谷四種情境：崩塌堵河且兩期持續 → A；只有單期 → B；沒有崩塌 → C；
崩塌只在湖面以上 → C。不貼河道的積水不列入。20 組隨機 speckle × 5 種情境，
每次都只有 1 個候選且分級正確。合成場景寫成 GeoTIFF 跑 `analyze_sar_change.py`，
有 DEM 時得 A，沒有 DEM 時得 B。

```bash
python -m pipeline.detect.barrier_lake   # 四種情境
python -m pipeline.detect.landslide
```
