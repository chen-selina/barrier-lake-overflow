# 事件研判規則

`pipeline/events/` 把 SAR 偵測結果整理成「事件」，再依時間逐期回放。
每張事件卡回答六件事：在哪裡、為什麼值得注意、有哪些證據、缺什麼、多重要、下一步做什麼。
每項判斷都記進 `rulesFired`，可以對回是哪條規則產生的。

SAR 在這裡只是證據來源之一。偵測端的 A/B/C 改稱「SAR 證據強度」，不當成最終判定。

## 流程

```
逐期 SAR 偵測（final_*.json）
  → 跨期追蹤：中心點相距 250 m 內視為同一事件
  → 每一期影像各是一個回放時點，只用當時已取得的影像
  → 每個事件：持續性 → 證據強度 → 優先等級 → 研判信心 → 證據缺口 → 建議任務
  → dashboard/data/events.js
```

回放時不會用到未來的資料。例如 7/23 那一期的複核結果要等 7/29 影像進來後才會出現。
偵測檔（`final_0722.json`）裡雖然已經有複核欄位，那個時點也不會用。

## 持續性

| 狀態 | 條件 |
|---|---|
| 已確認持續 | 任一期複核 IoU 達門檻，或在兩期以上都偵測到、且中間沒有複核失敗 |
| 待複核 | 只有單期，或複核影像還沒進來 |
| 複核未持續 | 最新一筆偵測的複核 IoU 未達門檻 |
| 持續性中斷 | 已確認過，但最新一期沒再偵測到，或最新複核未持續 |

複核未持續後又在同位置出現，回到「待複核」，不直接算確認。

## 優先等級（決策表，依序比對）

| 條件 | 優先 | 建議行動 |
|---|---|---|
| 持續性中斷 | 高 | 建議立即查證（可能潰決或排空） |
| 已確認持續＋附近有崩塌（A 級） | 高 | 建議立即查證 |
| 待複核＋附近有崩塌（B 級）＋他單位光學或航拍成果 | 高 | 建議立即查證（多源一致） |
| 待複核＋附近有崩塌（B 級） | 中 | 建議人工確認 |
| 待複核、附近無崩塌（C 級） | 低 | 暫時觀察 |
| 複核未持續 | 低 | 暫時觀察 |

同一等級內依面積由大到小排。

## 研判信心

| 信心 | 條件 |
|---|---|
| 高 | 需要 SAR 以外的獨立證據：他單位已發布的光學或航拍成果，或值班人員在儀表板上記錄「確認為堰塞湖」 |
| 中 | 已確認持續，或複核結果明確未持續（證據只有 SAR，最高就到這裡） |
| 低 | 只有單期 SAR，或前後期結果不一致 |

## 串接他單位既有成果

情境檔的 `externalEvidence` 記錄其他單位已發布的成果（時間、種類、位置、出處）。
某時點只用「當時已發布」且「位置在 radiusM 內」的成果：

| 種類 | 作用 |
|---|---|
| `optical`、`aerial` | 算 SAR 以外的獨立證據：單期 SAR 可直接升高優先、信心到「高」，並取消「光學影像」缺口 |
| 其他（如 `official` 官方估算） | 只列為背景，不影響優先與信心 |

`exposure` 記錄下游保全對象，有填就取消「下游保全對象」缺口。

馬太鞍溪目前填的都有出處（維基百科條目，引農村水保署等官方發布；NCDR 災害全紀錄）：
7/24 農村水保署 Planet 光學影像發現堰塞湖、7/27 航遙分署航拍、8/20 官方蓄水量估算、下游光復鄉與台 9 線馬太鞍溪橋。
發布時間只知道日期，一律當作當天 23:59 才取得（保守）。

## 事後查證（不參與研判）

情境檔的 `hindsight` 記錄回放結束後才做的查證，例如負案例用 Sentinel-2 確認 E1 不是水。
每筆有位置（`lonLat`、`radiusM`）、結論（`verdict`：`false_positive` 等）、說明、查證圖與方法。

- 依位置附到事件卡上，儀表板以虛線框標示「事後查證 · 回放當下系統不知道」，佇列上加「事後：誤報」標籤。
- **不改動任何研判結果**：優先等級、信心、任務都照回放當下的資料計算。這樣負案例才能誠實呈現系統當時會怎麼判。
- `run_sar_series.py` 重跑時會保留情境檔裡的 `description`、`hindsight`、`externalEvidence` 等人工整理欄位，
  只重新產生影像期別；要改說明可加 `--description`。

## 證據缺口

- 形成期間雨量：`observations.csv` 該欄空白時列出（馬太鞍溪目前仍查不到測站數字）
- 光學影像：沒有他單位光學或航拍成果時列出
- 下游保全對象：情境檔沒有 `exposure` 時列出
- 人工查證：值班人員記錄後消失

## 建議任務

| 優先 | 任務 |
|---|---|
| 高（已確認、多源一致） | UAV／現地查證壩體與湖面、調閱光學影像（已有他單位成果時改為「取得既有判釋成果，不重做」）、通報主管機關並評估下游、持續 SAR 監測、補查雨量 |
| 高（中斷） | 立即查證是否潰決或排空、調閱光學影像、通報主管機關 |
| 中 | 值班人員判讀證據圖、排下一期 SAR 複核、調閱光學影像、**暫不派遣 UAV** |
| 低 | 暫時觀察不派遣任務；同位置再出現時重新列入待複核 |

「暫不派遣 UAV」是刻意的：單期 SAR 暗區多數會在複核時消失（馬太鞍溪 4 個誤報全部如此），
先用複核過濾，避免浪費現地人力。

## 規模

SAR 事件只給相對級距，不換算蓄水量：湖面 ≥ 10 公頃為「大」、1～10 為「中」、< 1 為「小」（專案自訂）。
SAR 陡坡與陰影遮罩會擋掉約四成湖面，面積一律視為下限。

## 人工查證

儀表板上的查證紀錄（確認／持續觀察／排除、查證人員、補充說明）存在瀏覽器 localStorage，可匯出 JSON。
系統研判不會被覆寫，只在旁邊註記。紀錄只在記錄當下及之後的回放時點生效。

## 負案例（2026 汛期）

`scripts/gee_export_series_s1.js` 匯出同一窗格 2026 年汛期的逐期影像（降軌 105，17 期，2026-06-05～09-28），
`scripts/run_sar_series.py` 用同一組參數跑完並寫成情境，儀表板多一個「負案例」分頁。
這段期間窗格內沒有清冊登載的新堰塞湖；2025 年的湖已於 2026 年 1 月降挖排空（[自由時報](https://news.ltn.com.tw/news/Hualien/breakingnews/5571802)）。

整季只有一個事件 E1，位於壩址東側約 500 m 的崩塌堆積區，面積 0.6～1.4 公頃：

| 時點（台灣） | 高 | 中 | 低 | E1 狀態 |
|---|---|---|---|---|
| 6/6 | 0 | 0 | 0 | — |
| 6/7、6/19 | 0 | 1 | 0 | 待複核（0.6 公頃），建議暫不派 UAV |
| 6/12 | 0 | 0 | 1 | 複核未持續，降為觀察 |
| 6/24～7/19（6 個時點） | 1 | 0 | 0 | 已確認持續（0.6～1.0 公頃） |
| 7/25、7/31、8/24 | 1 | 0 | 0 | 持續性中斷（「可能潰決或排空」） |
| 8/12、9/5～9/29 | 1 | 0 | 0 | 已確認持續（0.7～1.4 公頃） |

以 Sentinel-2 查證 E1（2026-06～09，雲量 < 40% 共 12 期，其中 7 期 E1 範圍內雲與雲影 < 50%）：

| 檢查項目 | 結果 | 如果是水應該是 |
|---|---|---|
| Sentinel-2 地物分類（SCL） | 晴天 7 期全部是「裸露地表」或「暗色地表」，被判為水的像元 0 個 | 判為「水」 |
| 近紅外線（B8） | 1,200～1,800，與外圍一圈土石相近 | < 500（水幾乎完全吸收） |
| MNDWI | −0.08～0.04，與外圍差距 ≤ 0.03 | 明顯 > 0 |

唯一 MNDWI 偏高的 9/16（0.25）是 E1 被高雲 100% 覆蓋，不是水。同一批影像在河道上有判出水，表示分類本身是有效的。

**結論：E1 是誤報。** 光學上它就是崩塌堆積的一部分。SAR 會持續看到暗區，可能是堆積區上朝西陡坎的雷達陰影
（降軌從東向西照），或細顆粒泥砂平台太平滑、把雷達波反射走；沒有現地資料無法區分是哪一種。
兩者都是「事件前 DEM 看不到崩塌後新地形」造成的，和 2025 年的 4 個誤報在同一片崩塌地。

**這個負案例揭露兩個失效情境：**

1. **崩塌堆積區的持續暗區會被當成堰塞湖。** 暗區每期都在，跨期複核擋不下來，從 6/24 起一直列高優先。
2. **忽隱忽現的小暗區會觸發「持續性中斷」。** 這條規則是為「大湖突然消失＝可能潰決」設計的，
   但 E1 每漏偵一期就觸發一次，整季共 3 次「可能潰決或排空」。

**做對的地方：** E1 從頭到尾沒有 SAR 以外的佐證，研判信心最高只到「中」（待複核與中斷時為「低」），從未到「高」。
「只有 SAR 時信心最高到中」這條原則，正是為這種情況設計的。另外，2025 年湖所在的西側河谷在 2026 年已恢復為河道，
整季沒有誤報。

**沒有為此修改參數或規則。** 可能的改法（例如以事件型崩塌目錄劃出堆積區、消失需連續兩期才升高優先）
都是看過這個結果才提出的，尚未採用。
