# 事件研判規則

`pipeline/events/` 把 SAR 偵測結果整理成「事件」，再依時間逐期回放。
每張事件卡回答六件事：在哪裡、為什麼值得注意、有哪些證據、缺什麼、多重要、下一步做什麼。
每項判斷都記進 `rulesFired`，可以對回是哪條規則產生的。

SAR 在這裡只是證據來源之一。偵測端的 A/B/C 改稱「SAR 證據強度」，不當成最終判定。

## 流程

```
逐期 SAR 偵測（final_*.json）
  → 跨期追蹤：中心點相距 250 m 內視為同一事件
  → 每一期影像各是一個回放時點，只用當時已取得的影像
  → 每個事件：持續性 → 證據強度 → 優先等級 → 研判信心 → 證據缺口 → 建議任務
  → dashboard/data/events.js
```

回放時不會用到未來的資料。例如 7/23 那一期的複核結果要等 7/29 影像進來後才會出現。
偵測檔（`final_0722.json`）裡雖然已經有複核欄位，那個時點也不會用。

## 持續性

| 狀態 | 條件 |
|---|---|
| 已確認持續 | 任一期複核 IoU 達門檻，或在兩期以上都偵測到、且中間沒有複核失敗 |
| 待複核 | 只有單期，或複核影像還沒進來 |
| 複核未持續 | 最新一筆偵測的複核 IoU 未達門檻 |
| 持續性中斷 | 已確認過，但最新一期沒再偵測到，或最新複核未持續 |

複核未持續後又在同位置出現，回到「待複核」，不直接算確認。

## 優先等級（決策表，依序比對）

| 條件 | 優先 | 建議行動 |
|---|---|---|
| 持續性中斷 | 高 | 建議立即查證（可能潰決或排空） |
| 已確認持續＋附近有崩塌（A 級） | 高 | 建議立即查證 |
| 待複核＋附近有崩塌（B 級） | 中 | 建議人工確認 |
| 待複核、附近無崩塌（C 級） | 低 | 暫時觀察 |
| 複核未持續 | 低 | 暫時觀察 |

同一等級內依面積由大到小排。

## 研判信心

| 信心 | 條件 |
|---|---|
| 高 | 需要 SAR 以外的獨立證據：值班人員在儀表板上記錄「確認為堰塞湖」 |
| 中 | 已確認持續，或複核結果明確未持續（證據只有 SAR，最高就到這裡） |
| 低 | 只有單期 SAR，或前後期結果不一致 |

## 證據缺口（目前每張卡都會列）

- 形成期間雨量：`observations.csv` 該欄空白時列出
- 光學影像：尚未串接
- 下游保全對象：尚未串接（可接 BigGIS、內政部道路與聚落圖層）
- 人工查證：值班人員記錄後消失

## 建議任務

| 優先 | 任務 |
|---|---|
| 高（已確認） | UAV／現地查證壩體與湖面、調閱光學影像、通報主管機關並評估下游、持續 SAR 監測、補查雨量 |
| 高（中斷） | 立即查證是否潰決或排空、調閱光學影像、通報主管機關 |
| 中 | 值班人員判讀證據圖、排下一期 SAR 複核、調閱光學影像、**暫不派遣 UAV** |
| 低 | 暫時觀察不派遣任務；同位置再出現時重新列入待複核 |

「暫不派遣 UAV」是刻意的：單期 SAR 暗區多數會在複核時消失（馬太鞍溪 4 個誤報全部如此），
先用複核過濾，避免浪費現地人力。

## 規模

SAR 事件只給相對級距，不換算蓄水量：湖面 ≥ 10 公頃為「大」、1～10 為「中」、< 1 為「小」（專案自訂）。
SAR 陡坡與陰影遮罩會擋掉約四成湖面，面積一律視為下限。

## 人工查證

儀表板上的查證紀錄（確認／持續觀察／排除、查證人員、補充說明）存在瀏覽器 localStorage，可匯出 JSON。
系統研判不會被覆寫，只在旁邊註記。紀錄只在記錄當下及之後的回放時點生效。
