# 生成式 AI 使用聲明

依「行政院及所屬機關使用生成式AI參考指引」精神，誠實揭露本專案開發過程中
生成式 AI 工具的使用範圍與界線。

## 使用了哪些工具

**Claude（Anthropic，透過 Claude Code）**，是本專案開發過程中主要使用的
生成式 AI 工具，用於程式撰寫、文件整理、專案追蹤等技術執行環節（詳見下方
「用在哪些環節」）。

本文件由團隊主筆撰寫並確認；若團隊成員在自己負責的部分另外使用了其他
生成式 AI 工具（例如撰寫簡報文案、查找資料時使用 ChatGPT 等），請在此
補充列出，本文件目前僅涵蓋 Claude Code 這條有留下完整紀錄的協作軌跡。

## 用在哪些環節

- **程式碼撰寫**：`code/pipeline/` 底下各模組（清冊轉換、風險模型介接、
  成因歸因與敘述生成、水量平衡預報、水體萃取、DEM 蓄水量反演、淹沒模擬、
  人口暴露評估等）與對應的單元測試、`code/dashboard/` 前端儀表板程式碼。
- **文件撰寫**：`README.md`、`docs/` 底下的架構說明、資料源圖鑑、模組
  README 等技術文件的初稿與後續維護。
- **專案進度整理**：待辦事項與可行性評估的整理彙總，協助團隊掌握目前
  完成度與依賴關係，但**優先順序與範圍取捨的最終決定權在團隊**（例如是否
  執行 SAR 完整版偵測鏈、是否進行 0403/萬里溪案例回測，都是團隊依自身
  時程與資源判斷後決定，AI 僅提供分析與建議）。

## 明確排除：哪些不是 AI 生成

以下屬於本專案的核心產出，**皆為實測資料或明確公式計算的結果，不是 AI
生成的內容**，也不允許用 AI 生成的內容替代：

- **清冊資料**：75 筆堰塞湖紀錄，來自農業部農村發展及水土保持署官方清冊
  （`data/raw/taiwan-barrier-lakes.csv`），座標僅經過確定性的 TWD97 →
  WGS84 轉換，數值本身未經任何 AI 加工。
- **風險模型係數與判斷邏輯**：`pipeline/ingest/risk.py` 的邏輯迴歸係數
  來自訓練資料實際擬合結果；雨量特徵來自 CWA 開放資料 API 即時觀測，
  不是模型或 AI 推測值。
- **成因敘述的判斷依據**：`pipeline/attribution/` 採規則判定加模板填槽
  （見 `docs/attribution.md`），每一句輸出都附帶 `rules_fired` 稽核清單，
  可追溯到是哪條規則、哪個門檻產生的——刻意不使用 LLM 生成敘述文字，
  正是為了避免生成式 AI 在災防輸出這種需要可稽核性的環節裡編造內容。
- **回測與誤差率數字**（C1/C2，見待辦事項對照表）：一旦有真實資料跑出
  結果，會是模型計算或量測的真實輸出，不會用 AI 生成的示範數字冒充。
  目前程式裡標註為 `synthetic`／示範資料的部分（例如
  `dashboard/data/inundation.js` 的淹沒範圍多邊形），是用**合成地形**
  跑真實演算法得出，用途是驗證程式邏輯正確、示範資料管線可以串接，
  已在資料與畫面文字上明確標註「示範用合成資料，非真實觀測結果」，
  不會被當成正式評估數字使用。

## 團隊的角色

生成式 AI 在本專案中扮演的是**技術執行協作者**的角色：把團隊已經決定的
方向（選題、方法、驗證範圍）轉換成程式碼與文件；技術路線的可行性判斷
（例如本文件所附的可行性評估分級）由 AI 提供分析、團隊做最終決定；程式
邏輯是否正確、是否符合官方數字，仍由團隊透過測試與人工複核把關——本
專案的測試套件（`code/tests/`，見 `README.md` 目前狀態表）就是這層把關
機制的具體展現。
